# 第二阶段：本地编程闭环

状态：2026-09-25 已实现，自动化与真实模型验收通过。详细证据见 [VALIDATION-PHASE-2.md](./VALIDATION-PHASE-2.md)。

## 使用流程

1. 从侧栏打开「项目与编程」，用 macOS 目录选择器添加 Git 项目。普通子目录会归一到 Git 工作区根目录；同一路径重复添加不重复建项目。支持无首个 commit 的 Git 仓库。
2. 默认选择「读代码」，选择项目和问答模型，填写代码问题并点击「开始读代码」。无需计划或批准；回答直接显示在「对话与结果」，可继续提问，重启后保留历史和正常完成的问答上下文。
3. 需要修改代码时，选择「改代码」及规划/执行模型，填写需求并点击「生成修改计划」。也可以在已有对话输入需求，点击「生成修改计划」。普通「提问」始终使用只读工具，不会自动转为执行。
4. 在「计划与审阅」阅读目标、范围、不包含项、模块、步骤、命令、外部动作、验证和验收。问题未解决时补充答案；「要求修改 / 重新规划」生成新版本。旧版本可切换查看。
5. 点击「批准并执行」后才开放编辑和命令。修改模型选择后必须先重新规划；项目或模型配置变化会令原计划失效。
6. 「代码变更」切换执行前基线和整个工作区；「工具与验证」查看输入、输出、工作目录、PATH、耗时、退出码及验证状态。
7. 停止后保留已产生的文件变更；需要本机登录或其他交互时，在外部终端处理，再重新规划。不会自动回滚或重放命令。

所有项目会话默认打开「对话与结果」，按时间展示完整用户消息与智能体回答，包括历史规划说明和执行结果。工具过程单独放在「阅读记录」或「工具与验证」。

问答会话仍使用第一阶段的无工具模式。编程会话固定绑定项目，每个会话是一个编程任务，可产生多个计划和执行版本。同一计划只允许批准执行一次；后续工作需生成新版本。

## 权限与运行边界

Read 仅注册 `read_file`、`list_files`、`search_files`、`git_status`，直接回答，不注册计划、写入或命令工具。Plan 仅注册 `read_file`、`list_files`、`search_files`、`git_status`、`update_plan`。Execute 创建新的 Pi 会话，开放受控文件读写、精确编辑、非交互命令、步骤更新和暂停工具。所有模式不自动加载 AGENTS、Skills、MCP、插件扩展或命令模板。

文件工具拒绝 `..`、绝对路径、`.git`、指向项目外的符号链接及子模块内部路径。写入不通过符号链接；覆盖已有文件前需读取并核对内容指纹。Git 查询固定参数，关闭 fsmonitor、外部 diff、textconv 和可选索引写入。

Execute 的 shell 使用当前用户权限，不是项目级操作系统沙箱。计划与工具提示约束执行范围，并拦截直接的自动 commit/push/reset/clean、sudo 和常见后台常驻命令；不能保证用字符串规则阻止所有间接 shell 行为，也不能形式化证明命令遵守自然语言计划。只有明确接受计划中的文件写入和命令执行后才批准。

命令为 `/bin/zsh -c`，启用 `errexit` 和 `pipefail`，避免 `测试命令; echo 完成` 掩盖前序失败。继承服务环境，补充 Homebrew 和系统 PATH；工作目录固定为项目根目录，stdin 关闭，不提供 PTY。默认 120 秒，上限 600 秒。输出区分 stdout/stderr，取消发送 SIGTERM 后升级 SIGKILL；独立监控进程在父服务断开时清理受管进程组。主动脱离进程组的恶意程序不在这一保证内。

需要交互由常见密码/验证码提示识别或模型的 `request_local_action` 指明；不保证识别每一种 CLI 的交互协议，未识别的等待按超时处理。扩大范围调用 `request_replan`，立即封闭剩余执行工具，生成新版本；用户重新规划后再批准。

## 审批、恢复与数据

- SQLite 从 v1 事务迁移至 v2，保留旧模型、Ask 会话、消息和 Pi 映射；拒绝以旧代码打开未知的新版本数据库。
- 新增项目、任务、计划版本、批准、编程运行快照、工具记录、步骤、事件及幂等回执。编程历史与基线均只保存在本机 SQLite，Plan / Execute 使用独立 Pi 会话，连续 Read 恢复最近一次正常完成的只读会话。
- 计划 hash 绑定正文、版本、设备、项目、配置快照与工作区指纹。工作区指纹包含 HEAD、暂存区、受跟踪和非忽略文件的内容与模式，并纳入规划实际读取的忽略文件。
- 规划前后及执行前均核对工作区。批准记录和执行运行在同一事务创建；重复批准返回原运行，不重复执行。
- 配置保存会递增 revision，包括只更新 API Key 的情况，确保旧计划失效。密钥本体仍留在 Keychain。
- 全局只有一个活动模型请求；执行时可浏览其他会话。工具事件有持久化递增序号，通过 `codingEvents` 可追读；界面重连后读取完整任务状态和日志。
- 服务重启把活动任务、运行和工具记录标为中断，不恢复命令；中断前的输出与修改保留。解除项目登记不删除文件，重新添加同一路径恢复登记。

新增应用接口集中在 `packages/protocol/src/coding.ts`：项目管理、创建/查询项目任务、只读代码问答 `codingRead`、生成/修改/批准/拒绝计划、变更查询、日志分页和事件追读。取消继续使用 `runCancel`。新增的写请求均使用幂等 requestId。

## 差异和验证含义

「相对执行前基线」比较当前工作区和执行启动时保存的内容；「整个工作区」比较当前内容和 HEAD。两者都可能包含外部并发编辑，因此不把全部差异自动归因于智能体。已有用户修改不会被自动 stash、reset 或清理。

验证状态来自实际标记为 verification 的命令记录及退出码；同一命令重试以最近一次结果为准，先前失败仍保留在日志。运行完成不等于测试通过。没有运行验证时显示「未验证」，不从模型叙述推断通过数。智能体说明可能含解释错误，应以代码、diff 和真实命令记录为准。

## 本阶段明确限制

- 单工作区最多 20000 个文件；文件快照全部计算指纹，文本预览单文件最多 128 KiB，总预算 8 MiB；超出预算或二进制仅展示元信息。diff 预览最多 250000 字符。
- 文件工具单次读取 128 KiB、写入 256000 字符，搜索最多 100 条结果，目录列举最多 500 项；每轮最多 150 次工具调用。
- 每次工具调用保留最多 64000 字符输出；UI 标明截断，日志每页 25 条。基线包含项目内容，不是仅元数据，因此应用数据目录应按源码隐私要求管理。
- 当前模式为开发启动器管理；仍不提供 launchd、安装包、签名、公证或长期后台执行。
- 不实现普通非 Git 目录、子模块内部执行、自动 worktree、PTY、Skills/MCP/Chrome、云端或 Android 同步。
