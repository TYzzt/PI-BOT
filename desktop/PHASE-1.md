# 第一阶段目标：搭建可运行的 macOS 桌面问答应用

状态：用户已确认第一阶段完成；早期自动化与待验收记录保留在 VALIDATION.md。第二阶段见 PHASE-2.md 和 VALIDATION-PHASE-2.md，第三阶段（接入云端）见 PHASE-3.md。（2026-09 调整：原第三至五阶段顺延，云端接入提前为第三阶段。）所属项目：T-AGNET desktop。

## 可直接交给开发智能体的目标

在 T-AGNET/desktop 中搭建 Electron + React + TypeScript + Vite 桌面应用和独立 Node.js 本地服务，接入真实 Pi coding-agent SDK。用户能够配置模型、创建会话、发送问题、查看流式回复、停止生成，并在应用重启后继续查看历史及对话。使用 SQLite 保存应用状态，使用 macOS Keychain 保存模型密钥。完成可重复的启动流程、必要自动化检查和真实模型端到端验证，提供运行说明及验证记录。

## 交付范围

1. 工程骨架：UI、本地服务、共享协议、Pi 适配器分层；固定依赖版本及锁文件，提供启动、构建、类型检查和必要测试命令。
2. 界面：会话列表、聊天区、模型设置；展示服务连接状态、生成状态与可理解的错误。
3. 本地服务：独立于 renderer 和 Electron 主进程运行，通过受控 IPC 连接；具备健康检查、单实例约束、断连提示与重新连接能力。
4. Pi 接入：SDK 驱动真实模型，支持多轮上下文、流式输出、取消与错误处理；首版 Ask 不启用 shell、文件写入、MCP 或自动发现的可执行项目扩展。
5. 模型配置：provider/API 类型、base_url、model_id、API key，支持保存、编辑、删除、选为默认和连接测试；至少完成一种 Pi 支持的真实提供商适配验证，不宣称所有兼容接口均可用。
6. 持久化：SQLite 保存会话、消息、模型非敏感配置和运行状态；Pi 会话单独存储，以内部映射关联；重启后恢复多轮对话上下文。
7. 凭据：API key 存入 Keychain，普通配置、数据库、日志和 renderer 状态不保留明文密钥；仅录入时经受限 IPC 传给凭据处理层。
8. 文档：README 写明前置依赖、启动和停止、配置模型、运行检查、数据位置和已知限制；提交真实验收记录。

## 本阶段必须定下的接口边界

- 应用主键采用 conversation_id、task_id、run_id、message_id；Pi session_id 只是内部映射。
- Pi 事件经 adapter 转为应用事件，React 不依赖原生 Pi 事件结构。
- 消息预留 shared/local_only 可见性，本阶段所有内容仅本地存储，不实现上传。
- 模型配置与模型密钥分离，UI 只读取凭据状态。
- renderer 启用 contextIsolation 与 sandbox，关闭 nodeIntegration，仅使用白名单 IPC。
- 用户取消与实际运行结束区分；按照锁定 Pi 版本的最终完成语义更新运行状态。

## 验收标准

| 编号 | 验收动作 | 通过条件 |
|---|---|---|
| P1-01 | 按 README 在目标 Mac 安装依赖并启动 | 桌面窗口和独立服务正常启动，界面显示连接成功 |
| P1-02 | 配置一个有效模型并测试连接 | 完成真实 API 调用；成功与失败结果明确 |
| P1-03 | 创建会话发送问题 | 回复真实来自 Pi SDK，逐步显示，无 mock 冒充 |
| P1-04 | 同会话发送依赖上文的问题 | 模型保留该会话上下文；另一会话不混入历史 |
| P1-05 | 在生成过程中停止 | 请求传递到执行服务，结束后状态一致，后续还能发送 |
| P1-06 | 退出并重新启动应用与服务 | 会话和消息保留，可继续多轮对话，密钥无需重复录入 |
| P1-07 | 使用无效密钥、断网或终止本地服务 | UI 显示对应失败/断连，未完成运行不被标成成功，恢复后可继续使用 |
| P1-08 | 在 Ask 中要求运行命令或改文件 | 执行能力未开放，不能通过默认工具或扩展意外执行 |
| P1-09 | 检查配置、数据库及日志 | 没有明文 API key；应用主键与 Pi 私有会话映射清楚 |
| P1-10 | 执行构建、类型检查及关键行为测试 | 检查通过，真实模型验收单独记录模型、日期及结果 |

只有全部标准有对应证据，才标记第一阶段完成。没有有效 API key 时可以继续完成工程与本地测试，但真实模型验证记为未完成，不能用模拟回复代替验收。
